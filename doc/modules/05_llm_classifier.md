# 模块 05：LLM 分类推理

_负责在候选标签空间内调用 LLM 完成分类，并尽量减少调用次数和输出不确定性。_

---

## 功能边界

LLM 分类模块接收已经通过预算检查的 `messages`，调用 `self.call_llm(messages)`，返回原始模型输出。它不负责训练记忆，也不直接决定非法输出的兜底标签。

| 输入 | 输出 |
| --- | --- |
| 不超预算的 `messages` | LLM 原始文本输出 |

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 单轮分类 | 默认路径，成本最低 |
| 候选内判别 | 明确只能选择候选标签 |
| 低置信度触发 | 仅在必要时调用 verifier |
| 多数投票可选 | 对极难样本使用，但成本高 |
| 思考长度控制 | 不鼓励长 CoT，避免浪费 token 和破坏输出 |

## 推荐策略

### 默认单轮

正式评测样本多，默认应只调用一次 LLM。单轮路径包括：

1. 候选标签召回
2. few-shot Prompt
3. LLM 输出标签
4. 解析器校验

### 条件二次调用

只有满足以下条件之一时，才考虑二次调用：

- 第一次输出不是合法标签
- 输出包含多个标签且无法确定
- 候选检索最高分与第二名非常接近
- 当前文本与训练样例相似度整体很低
- 本地验证证明二次调用能显著提升准确率

### 不推荐默认长链式推理

分类任务通常不需要长 CoT。长解释会带来三个问题：

| 问题 | 影响 |
| --- | --- |
| 输入/输出成本变高 | 评测更慢，预算压力更大 |
| exact match 风险 | 模型可能输出解释而不是标签 |
| 幻觉理由 | 理由看似合理但标签错误 |

## 技术方案

### 纯标签调用

```python
raw = self.call_llm(messages)
label = self._parse_label(raw, candidates)
```

### JSON 调用

调试阶段可让模型输出：

```json
{"label":"候选标签","confidence":0.87}
```

但最终 `predict` 仍应只返回解析出的 `label`。

### 候选重排

二次调用可以只给 top 3-5 候选，要求模型比较边界：

```text
请只在以下标签中重新选择一个：...
第一次输出不合法或不确定。仍然只输出标签。
```

## 与其他模块的接口

```python
def _classify_with_llm(self, messages):
    return self.call_llm(messages)
```

分类模块越薄越好。复杂度应放在检索、预算、解析和兜底里，便于调试。

## 成本控制

| 策略 | 成本 | 准确率潜力 | 建议 |
| --- | ---: | ---: | --- |
| 单轮纯标签 | 低 | 中高 | 默认 |
| 单轮 JSON | 中 | 中高 | 调试可用 |
| 二次 verifier | 中高 | 高 | 低置信度触发 |
| self-consistency 多采样 | 高 | 不稳定 | 不建议默认使用 |

## 风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 模型输出候选外标签 | exact match 错误 | 解析器映射回候选或合法标签 |
| 模型被输入诱导 | 按用户文本指令输出 | Prompt 明确输入是不可信数据 |
| 调用过多 | 评测超时或成本过高 | 默认单轮，二次调用门控 |
