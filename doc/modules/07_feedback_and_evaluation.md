# 模块 07：反馈记忆与实验评测

_负责记录策略效果、错误模式、混淆标签和 token 成本，支撑后续优化与探索报告。_

---

## 功能边界

反馈与评测模块主要用于本地开发和报告，不应在正式预测时读取测试标签或写磁盘。它可以在本地实验后帮助更新策略、总结混淆规则和设计 ablation。

| 输入 | 输出 |
| --- | --- |
| 预测结果、真实标签、本地运行统计、token 统计 | 指标、混淆分析、策略对比、报告材料 |

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 指标记录 | accuracy、macro-F1、平均 token、调用次数 |
| 错误分析 | 找出 top 混淆标签对 |
| 策略对比 | 记录每个 harness 版本的变化和效果 |
| 记忆更新建议 | 将可靠错误模式转为 hard negative 或规则 |
| 报告素材 | 为主观评分提供方法论和证据 |

## 实验路线

| 版本 | 内容 | 目标 |
| --- | --- | --- |
| `B0` | 全标签 + 少量固定示例 | 建立最低基线 |
| `B1` | 相似样例检索 + 全标签 | 验证样例检索 |
| `B2` | 候选标签检索 + 候选内分类 | 验证标签压缩 |
| `B3` | 候选标签 + hard negatives | 改善混淆边界 |
| `B4` | 低置信度 verifier | 用少量额外调用提升困难样本 |
| `B5` | cheatsheet 规则 | 验证外部经验记忆 |

## 指标定义

| 指标 | 公式或含义 | 价值 |
| --- | --- | --- |
| Accuracy | 正确数 / 总数 | 主评分相关 |
| Macro-F1 | 各类 F1 平均 | 防止只优化高频类 |
| 平均 prompt token | prompt token 总数 / 样本数 | 衡量预算效率 |
| 平均调用次数 | LLM 调用数 / 样本数 | 衡量成本和速度 |
| 非法输出率 | 非合法标签输出数 / 样本数 | 衡量解析和 Prompt 稳定性 |
| top 混淆对 | 高频错误标签对 | 指导 hard negatives |

## 混淆分析

错误样本应被整理成“标签边界”而不是长篇案例。示例：

```text
退货退款 vs 催发货：如果用户询问物流速度或发货时间，优先催发货；只有明确要求退款、退货、取消订单，才选退货退款。
```

这类规则可以进入 cheatsheet，但必须短、少、只在相关候选标签出现时进入 Prompt。

## 正式评测注意事项

| 注意事项 | 原因 |
| --- | --- |
| 不读取测试标签 | 规则禁止，且会造成不真实分数 |
| 不写磁盘缓存 | 提交环境可能禁止或不稳定 |
| 不默认多轮调用 | 样本量大时容易超时 |
| 不硬编码 DEV 答案 | OOD 任务会失败，且违反要求 |

## 与 `doc/think.md` 的关系

`doc/think.md` 用来记录真实开发过程；本模块文档提供记录结构和指标定义。每次关键实验建议同步写入 `doc/think.md`，包括改动、命令、结果和判断。
